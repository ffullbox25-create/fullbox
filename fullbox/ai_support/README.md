# ИИ-поддержка Fullbox

Первый этап коммуникации сотрудников с ИИ-программистом.

## Реализовано

- создание обращения с привязкой к зоне и заявке;
- автоматический контекст страницы без сохранения внешнего hostname;
- переписка сотрудника, ответственного и ИИ-агента;
- статусы диагностики и исправления;
- журнал предлагаемых действий агента;
- разграничение видимости обращений;
- программная политика безопасных действий.

## Политика действий

- чтение логов, базы и сервисов, воспроизведение вне production, подготовка
  патча и тесты разрешены автоматически;
- выкладка, перезапуск сервиса и коррекция статуса одной заявки требуют
  подтверждения человека;
- остатки, движения, массовые данные, схема базы, права, новые функции и
  архитектура всегда блокируются для ИИ-агента и передаются программисту.

## Текущая граница этапа

Модуль создаёт коммуникационный контур и безопасную очередь действий. Worker
диагностики подключается отдельно и запускается только после явного включения.

## Диагностический worker

`python manage.py process_ai_support --dry-run` показывает очередь, ничего не
изменяя. Для реальной диагностики нужны все три настройки production:

- `AI_SUPPORT_DIAGNOSTICS_ENABLED=true`
- `OPENAI_API_KEY=...`
- `AI_SUPPORT_OPENAI_MODEL=...`

Worker отправляет в OpenAI Responses API только сокращённый и очищенный
read-only снимок. Формат ответа задаётся строгой JSON-схемой; tools отключены,
а `store=false`. Worker может записывать лишь диагноз, ответ сотруднику, статус
обращения и аудит собственного действия. Команды модели, shell и SQL не
исполняются.

## Проверка

```bash
DJANGO_SETTINGS_MODULE=ai_support.test_settings python manage.py test ai_support
python manage.py makemigrations --check --dry-run ai_support

```
