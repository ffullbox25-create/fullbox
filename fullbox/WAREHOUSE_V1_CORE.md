# Первая волна warehouse-core

## Что вводим первой миграцией

В первую волну я зафиксировал и вынес в код такие модели:

- `WarehouseLocation`
- `WarehouseContainer`
- `WarehouseReserve`
- `WarehouseOperation`
- `WarehouseOperationTask`
- `WarehouseEvent`
- `WarehouseStockSnapshot`

## Почему именно они

Это минимальное ядро, которого уже достаточно, чтобы строить склад как источник истины:

- есть физическая точка хранения;
- есть контейнер;
- есть резерв;
- есть операция;
- есть исполнимая задача;
- есть журнал событий;
- есть текущий materialized snapshot.

## Что пока сознательно не вводим

Во вторую волну можно добавить:

- `warehouse_stock_unit`
- `warehouse_context`
- `warehouse_stock_unit_link`

Они нужны для полной правильной модели, но не блокируют старт ядра.

## Практический смысл v1

Эта первая волна уже позволяет:

- проектировать write-path;
- материализовать текущее состояние;
- перестать размазывать складскую правду между UI-логикой и документными таблицами.
